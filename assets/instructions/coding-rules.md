# Project Instructions: Coding Rules

タスクによらず常に成り立つ規則。手順は Skill 側、今回の指示は Step プロンプト側にある。

## 対象ディレクトリ

このワークフローの成果物・状態ファイルはすべて **`.ai-workflow2/`** 配下にある（末尾に `2` が付く）。

リポジトリには旧ワークフロー **`.ai-workflow/`（`2` なし）** も存在し、同名ファイル
（`codex-prompt.md` / `current-result.md` / `backlog.md` 等）があるが**別物**。

- 読む入力も書き出す成果物も、**必ず `.ai-workflow2/` 側**を使う
- 旧 `.ai-workflow/` には**書き込まない**。原則読まない
  （`codex-prompt.md` が明示的に参照を指示したファイルのみ、その指示に従って読み取り可）

## 変更範囲

- 変更してよいのは `codex-prompt.md` の `# Scope Boundaries` / `# Required Changes` の範囲内だけ
- 範囲外のファイルに触れる必要が生じたら、勝手に広げずに成果物へ書いて上げる
  （implementation は `## Deviations`、fix は Fix Scope 外として明記する）
- 無関係なリファクタリング・ついでの整形・正当化のない広範なリポジトリ探索をしない
- `context-package.md` を最小コンテキストとして使う。そこに書かれていないファイルを
  読む必要が出た場合、それ自体が research の漏れなので成果物に記録する

宣言と実際の差分は `diff-scope` validator が機械的に突き合わせる
（implementation は report、fix は halt）。手で守る規則ではなく、検査される規則である。

## テスト実行

実行する範囲も具体的なコマンドも `codex-prompt.md` の `# Required Tests` に従う。
そのうえで、次は常に守る。

- **最終検証の e2e は1コマンドにまとめる。** 複数の spec を実行する場合は **1回の呼び出し**で渡す。
  spec ごとに分けて呼ぶと、その都度 `webServer`（起動タイムアウト 120〜180秒）が再起動し、
  待ち時間が本数分だけ積み上がる
- ⚠️ **開発中の一時的な絞り込み検証はこの限りではない。**
  修正の途中で対象を絞って回す（一時 spec / 単一テスト / 単一 spec）のはむしろ推奨で、
  **バックエンドは一度起動したら維持してよい**。フルスイートは**修正が揃ってから1回**でよい。
  ⚠️ **一時 spec・一時コードは完了前に必ず削除する。**
- **再試行しない**（`--retries=0` 相当）。既定で再試行する設定だと失敗時の所要時間が倍になる。
  フレークの切り分けが目的でない限り再試行しない
- **恒久的なテストを自己判断で追加・変更しない。** `# Required Tests` の範囲が不足していると
  判断した場合は、追加実行せずに `current-result.md` の `## Deviations` へその旨と理由を書く
  （上の「開発中の一時的な検証」は、完了前に消すので恒久的なテストにあたらない）

## 検証していないものを成功側へ丸めない

`PASS` / `FAIL` / `NOT VERIFIED` のような三値を二値へ潰さない。実行できなかった・
環境がなかった・時間が足りなかった、いずれも `NOT VERIFIED` であって失敗ではない。
理由を1行添えれば足りる。

`Evidence` には**実在するもの**だけを挙げる。後段が実在を突き合わせるため、
存在しないテスト名・ログパスを書くと Major 以上の指摘になる。
