# Project Instructions: Knowledge Files

`context.md` と `learnings.md` に何を書き、何を書かないか。
reflection が更新し、task-planning と research が読む。**書く側と読む側で同じ基準を使う。**

## context.md — プロジェクトの現在の姿

判定基準: **次のタスクの計画時に、知らないと間違える情報か。**

書くもの:

- アーキテクチャ上の構造・制約で、今回判明したもの
- 変更された前提（依存関係、設定、外部との契約）
- 「この部分はこうなっている」という現状の記述

書かないもの:

- 今回の作業経過（archive にある）
- 一度きりの事象

## learnings.md — 行動を変える教訓

判定基準: **次に同じ状況が来たとき、行動が変わるか。** 変わらないなら書かない。

書くもの:

- 特定のやり方で失敗した／うまくいった、という再現性のある知見
- このプロジェクト固有の落とし穴とその回避手順

書かないもの:

- 一般的なベストプラクティス（モデルが既に知っている）
- 「〜に注意する」だけで、具体的な行動が伴わないもの
- 今回のタスクの説明

## 重複を増やさない

**既存項目の更新を優先し、似た内容を追記しない。**
知識ファイルは毎タスク単調増加すると、やがて読まれなくなる。

- 既存記述と矛盾するなら、**古い方を書き換える**（両方残さない）
- 既存記述の具体化なら、**その項目に統合する**
- 完全に新しい場合のみ追加する
