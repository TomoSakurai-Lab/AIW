# マイルストーン依頼プロンプトのテンプレート

`tools/aiw` に新しいマイルストーン（M2, M1.5 …）を足すとき、
Claude Code へ渡す依頼プロンプトの雛形。

M0.4 / M1 / M1.5 / M2 で実際に使った構成を抽出したもの。
**節を減らしてもよいが、「進め方」と「完了条件」は必ず残す**（省くと成果物が検証できなくなる）。

> このファイルは M2 レビューの再発防止として新設した。
> テンプレートをリポジトリ外（メモ等）でも持っている場合は、
> **「進め方」の由来記録の1行を同じ内容で反映すること。**

---

## 雛形

```markdown
# <マイルストーン名>

## 背景

<なぜ今これをやるか。可能なら実測を1つ引く。
 「〜だと思う」ではなく「〜が N 回起きた」の形で書く>

## 目的

<このマイルストーンで何が変わるか。1〜2文>

## スコープ

やること:
- <箇条書き>

**やらないこと**:
- <明示的に外すもの。特に「ついでに直したくなるが今回は触らない」もの>

## 段階

Stage 0: <調査・分類。承認を挟むならここで区切る>
Stage 1: <以降、1段階 = 1コミット>
...

## 進め方

- 実装前に既存コードを読む。既存の型・命名・エラー処理の流儀に合わせる
- 段階ごとに `npm run build` と既存テストを通す
- **指示・規則を新規に追加した場合は、既存の分類・設計文書に由来を記録し、
  完了報告で明示すること**
- <このマイルストーン固有の進め方。例: 「executor には触れない」
  「aiw run には触れない（不変条件1）」>

## 完了条件

- <機械的に確認できる形で書く。「〜が改善されている」ではなく
   「〜のテストが通る」「〜が N 行である」>
- npm test が通る

## コミット

<何コミットに分けるか。`git add <path>` で明示。
 複数行メッセージはヒアドキュメントで `git commit -F -`>
```

---

## 「進め方」の由来記録について

M2 で、`implementation` の Skill に元のプロンプトへ無かった注意書きが1件足された
（`Manual Verification Required` / `Unresolved Decisions` を空にしたい誘惑への注意）。
内容は妥当だったが、**分類表には出所が残らず、完了報告でも触れていなかった**ため、
レビューで「出所不明の追加」として指摘された。

今回は良性だったが、**承認なしの新規指示が常に良性とは限らない。**
分解や移行の作業では「移したもの」と「足したもの」が同じ表に並ぶため、
区別しないと後から差分を追えなくなる。

記録先の例:

| 作業 | 記録先 |
| --- | --- |
| プロンプトの分解・移行 | `docs/m2-prompt-decomposition.md` の分類表（分類「新規追加」） |
| 既知の不具合・死んだ指示の解消 | `docs/aiw-known-issues.md` |
| 設計判断 | 対応する `docs/design-*.md` |
